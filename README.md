# mesh_to_points

Turn a container mesh (PLY, STL, OBJ, OFF, GLB/GLTF, 3MF, ...) into an **ordered,
region-aware point set for a wiping end-effector**. Every point carries

| field | meaning |
|---|---|
| `tool_pos` (x y z) | point on the surface the tool touches |
| `tool_dir` (dx dy dz) | unit vector pointing **into** the material (= `-norm_dir`) |
| `norm_pos` (x y z) | same as `tool_pos` |
| `norm_dir` (dx dy dz) | outward unit surface normal |
| `region`, `level` | `rim`, `inner_wall`, `tread`, `inner_floor`, ... and terrace level |
| `stroke` | id of the continuous stroke; a new id means "lift and move" |
| `reachable` | surface is visible from straight above |

Units are **metres**, Z is up by default, the default spacing is **0.01 m**.

The "intelligence" is a geometric segmentation of the mesh: faces are classified
into rim, inner wall, tread (terrace step), inner floor, inner overhang, outer wall
and bottom. By default only `rim + inner_wall + tread + inner_floor` get points and
surfaces that cannot be reached from above are dropped, which is what a wiping task
needs. Everything is configurable.

## Single-file version

`mesh_to_points_allinone.py` is the whole package merged into one standalone file (generated by
`tools/build_allinone.py`; rebuild it after editing the package). Copy it anywhere that has the
dependencies installed:

```bash
python mesh_to_points_allinone.py shapes --out test_meshes                 # test meshes
python mesh_to_points_allinone.py test_meshes/dog_bowl.ply -o output --viz --png
python -c "import mesh_to_points_allinone as m2p; r = m2p.generate('test_meshes/bucket.ply'); print(len(r.points))"
```

## Quick start

```bash
# test meshes (metres, Z-up) -> test_meshes/*.ply + *.stl
.venv/bin/mesh2points-shapes --out test_meshes

# points + interactive viewer for one mesh
.venv/bin/mesh2points test_meshes/dog_bowl.ply -o output --viz --png
#   -> output/dog_bowl_points.csv  dog_bowl_points.npz  dog_bowl_meta.json
#      output/dog_bowl_viz.html (open in a browser)  dog_bowl_preview.png

# everything: all shapes x patterns, with viewers and an index page
.venv/bin/python examples/run_all.py           # -> output/index.html

# tests (46 tests, ~45 s; the script disables ROS's auto-loaded pytest plugins)
./run_tests.sh
```

Python API:

```python
from mesh_to_points import generate
from mesh_to_points.viz import plotly_html

res = generate("test_meshes/bucket.ply", spacing=0.01, row_spacing=0.02, pattern="spiral")
pts = res.points                     # ordered, in the input mesh frame
pts.pos, pts.tool_dir, pts.normal    # (N,3) arrays; pts.stroke, pts.region_names, pts.level
res.save("output", "bucket")         # csv + npz + json
plotly_html(res, "output/bucket_viz.html")
```

## Options (CLI flags = `generate()` keyword arguments)

| flag | default | effect |
|---|---|---|
| `--spacing` | 0.01 | distance between consecutive points along a stroke [m] |
| `--row-spacing` | = spacing | distance between rings / scan lines [m]; set it to your wiper width |
| `--margin` | row/2 | inset of the first ring / line from region edges |
| `--pattern` | spiral | `spiral` (contour-parallel rings, outside-in, top-down), `zigzag` (boustrophedon), `poisson` (blue-noise samples) |
| `--order` | auto | `auto` keeps the pattern's own order (poisson -> `tsp`); `nearest` = greedy nearest neighbour; `tsp` = nearest neighbour + 2-opt/Or-opt improvement; `none` |
| `--continuous` | off | spiral: blend the rings into one continuous helix per region (no lifts) |
| `--zigzag-angle` | 0 | scan-line direction on flat regions [deg] |
| `--include` | rim,inner_wall,tread,inner_floor | regions to cover, or `all` |
| `--exclude` | | regions to drop (e.g. `rim`) |
| `--no-reachable-filter` | off | keep surfaces hidden from above (e.g. under a vase shoulder) |
| `--up` | z | `z -z x -x y -y`, `auto` (largest flat resting base), or `x,y,z` |
| `--scale` | 1 | multiply input coordinates; use `0.001` for millimetre meshes |
| `--top-angle` / `--bottom-angle` | 45 / 45 | normal angle thresholds for top- / down-facing faces |
| `--crease-angle` | 15 | dihedral angle that separates adjacent top regions (rim vs. a sloped floor) |
| `--normal-smoothing` | 30 | crease angle for smooth point normals; `0` = flat face normals |
| `--flip-normals` | off | invert the mesh orientation after the automatic fix |
| `--viz --open --png --ply --seg-mesh` | | interactive HTML / open it / static PNG / point-cloud PLY / segmented mesh PLY |

### Output files

* `<name>_points.csv`: `idx,stroke,region,level,reachable,tool_x,tool_y,tool_z,tool_dx,tool_dy,tool_dz,norm_x,norm_y,norm_z,norm_dx,norm_dy,norm_dz`
* `<name>_points.npz`: `tool_pos, tool_dir, norm_pos, norm_dir, stroke, region, region_id, level, reachable, face`
* `<name>_meta.json`: parameters, statistics (path length, spacing statistics, points per region), region areas
* `<name>_viz.html`: standalone interactive viewer; legend toggles mesh regions, points, path, `tool_dir`
  cones (red, into the surface), `norm_dir` cones (green, out), order labels; the slider replays the order
* optional `<name>_points.ply` (point cloud with normals + order) and `<name>_segmented.ply` (mesh with region colours)

## How it works

1. **Load & clean**: trimesh loader, merge/degenerate-face cleanup, optional scale, rotation into an
   internal Z-up frame, conforming midpoint refinement so no edge is longer than `0.6 * spacing`,
   consistent outward normals (signed volume for closed meshes, ray-parity vote / open-side rule for scans).
2. **Segment** (`segment.py`): orientation vs. up (top / side / down) -> enclosure test by casting a
   horizontal ray along the face normal (hits the mesh = looks into a cavity -> inner, else outer) ->
   top-facing components split at creases: the ones touching the exterior are the **rim**, the rest are
   **treads** / the **inner floor** by height level; inner walls get the level of the step they belong to.
   Small components are merged (noise robustness). **Reachability** = face centroid visible from +Z.
3. **Sample** (`sample.py`):
   * `spiral`: heat-method geodesic distance from the rim's outer edge over the whole selected surface,
     iso-rings every `row_spacing`, each resampled every `spacing`; rings are ordered by a depth-first
     walk of the contour tree (outside-in, top-down; nested cavities one after the other), each starting
     next to where the previous ring ended. `--continuous` blends rings into a helix.
   * `zigzag`: per region piece, chained rim -> nearest -> ... -> floor: scan lines on wide flat regions,
     serpentine rings on walls, annular tops and narrow regions (a single centre-line stroke when only one
     ring fits).
   * `poisson`: blue-noise samples at grid-equivalent density, ordered with `tsp`.
4. **Normals**: crease-aware smooth normals interpolated from the mesh (sharp edges stay sharp);
   `tool_dir = -norm_dir`.
5. Results are mapped back to the input frame.

## Test shapes (`mesh2points-shapes`)

`dog_bowl` (thick, filleted floor, wide rim), `vase` (curved S-profile, fully reachable), `bucket`
(thick tapered wall), `terraces` (three concentric steps + floor) plus `hemisphere_bowl` (no sharp
wall/floor transition), `plate` (shallow slope), `rect_tray` (two compartments, from booleans, very coarse
input mesh), `vase_necked` (bulge + narrow neck: exercises the reachability filter) and `scan_bowl`
(noisy, non-watertight, holes).

## Notes / limitations

* Meshes must be one object; attached parts such as a handle may be labelled `inner_wall` where they
  face the body.
* `reachable` is a visibility test along the up axis, not a collision check with a real tool.
* The spiral pattern skips narrow ribs inside a region (e.g. a thin divider top); use `zigzag` there.
* Very large meshes: refinement is capped at 2M faces; lower the density or pass `--no-refine`.
* `--continuous` (helix): on elongated floors the last turn runs alongside the final ring (overlap, no gap);
  the spiral into the centre tightens its steps to about half the spacing.
